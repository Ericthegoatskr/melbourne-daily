# Melbourne dashboard visual system

The entrance homepage defines the shared visual style for the Melbourne dashboard collection. The [Weather & UV dashboard](https://ericthegoatskr.github.io/melbourne-daily/weather.html), [EPA air-quality dashboard](https://ericthegoatskr.github.io/melbourne-daily/air.html) and [PTV transport dashboard](https://ericthegoatskr.github.io/melbourne-daily/transport.html) are dedicated pages in the same application, linked from their homepage cards. Parking Explorer remains a separate application with the same palette and motion language.

## Visual language

The default palette uses navy `#14213D` for the canvas and navigation, cream `#F4EDE0` for data surfaces, and coral `#FF6B5B` for actions. The reference's 60/30/10 balance is a visual guide, not a restriction on semantic data colours. Source-provided EPA categories, the UV scale and parking availability keep their established meanings. Coral buttons use navy text; small coral text on cream uses a darker accessible shade. Rounded cards, fine borders and shallow shadows separate information without sacrificing contrast. Keep Australian English, Melbourne time and existing source attribution.

The sidebar's Colour theme switch restores the original light palette. Its preference uses `melbourne-collection:theme` on the shared GitHub Pages origin, applies before React paints and synchronises across tabs. It works for the current page even when storage is unavailable. Keep `ThemeSwitcher.tsx`, `CollectionNav.css` and `navy-theme.css` identical in both repositories. Theme overrides are scoped to `html[data-theme="navy"]`; `navy-pages.css` and Parking's `navy-parking.css` cover app-specific surfaces. Do not alter layouts, motion or data adapters to switch palettes.

Theme variables are defined in `src/styles/tokens.css` and consumed by `src/styles.css`. Weather-page layout rules live in `src/WeatherDashboard.css`, scoped to `.weather-dashboard` and `wx-` classes so they do not change the homepage. Air-quality layout rules live in `src/AirDashboard.css`, scoped to `.air-dashboard` and `aq-` classes. The weather page reuses `Forecast`, `WeatherScene`, `ValueChange` and the existing feed adapters; the air-quality page reuses the EPA contract, per-field expiry and regional-model adapter. A later dashboard can reuse these tokens without inheriting the entrance page's layout. Keep data adapters independent of presentation.

## Collection navigation

Use the same five destinations in this order: Home, Parking, Weather & UV, Air quality and Transport. `CollectionNav` supplies the series navigation on every page. Page destinations are normal same-tab links; `aria-current="page"` marks the current dashboard. Existing section anchors remain separate under “On this page” and use `aria-current="location"` when selected.

Desktop sidebars show the series links before the compact section list. At mobile widths, the five destinations also appear in a fixed bottom bar with short visible labels and full accessible names. Keep each target comfortably touchable, allow for the device safe area and reserve enough page space so the bar cannot cover the footer or parking-map controls. Hide the bottom bar while the modal navigation drawer is open.

All Daily pages share `useNavigationDrawer` for scroll locking, initial focus, Tab wrapping, Escape dismissal and closing on a return to desktop width. The Parking application follows the same behavior. The two repositories keep compatible component markup, link order and styles; a navigation change must be checked and deployed in both applications. Links use the fixed root-relative GitHub Pages paths under `/melbourne-daily/` and `/melbourne-parking-dashboard/`, so both production builds can also be tested together on one local origin.

## Interaction and motion

- Summary cards link to the corresponding section and share the same freshness checks as the detailed card. A missing or expired reading remains unavailable.
- `Forecast` renders actual hourly temperature and rain probabilities on separately labelled axes. Its pointer, touch, keyboard slider and hourly buttons select the same reading. The three-day view retains local calendar dates.
- `WeatherScene` is a decorative SVG illustration derived from the weather code and day/night flag. The text weather description remains the accessible description.
- `ValueChange` fades and moves the real reading when it changes. It never counts through invented intermediate measurements.
- The dedicated weather page keeps station UV and model UV visibly separate. Its hourly UV chart uses actual model values; zero has a baseline mark and missing readings have dashed marks. It never turns a missing value into zero.
- The daylight arc uses the selected suburb's sunrise and sunset for today's Melbourne calendar date. It represents elapsed daylight, not the sun's position in the sky, and carries a text description alongside the diagram.
- The air-quality page shows the official EPA category without deriving a replacement from pollutant values. PM2.5 and PM10 retain their units, one-hour averaging period and individual observation times. Missing fields remain unavailable; a valid measurement of zero remains visible.
- Nearby EPA stations are ordered by distance within 100 km. The nearest reporting station is the default. Search filters the list without changing the selected readings; manual selection updates the cards. If a selected station stops reporting, explain the fallback to the nearest eligible station. “Use nearest station” restores automatic selection.
- EPA observations and regional CAMS / Open-Meteo estimates stay in separate cards with separate source status. Decorative artwork and pastel card backgrounds do not imply air quality, an AQI value or a trend absent from the source.
- The transport workspace reuses `CommutePanel` and its existing stop/direction identity, saved selections, data adapter and expiry rules. Search and local favourites work independently of live-data activation. Departures and service updates have separate panels, each explicitly awaiting activation while the PTV connection is unavailable. Missing service data never becomes a claim that services are running normally.
- `TransportScene` is a decorative tram illustration with a finite entrance animation. It is not a route map, vehicle tracker or indication of a departure. Transport-page layout is scoped to `.transport-dashboard` and `tr-` classes in `src/TransportDashboard.css`; the workspace variant has its own scoped panel styles.
- Entrance and chart animations are finite; hover transitions are short. `prefers-reduced-motion: reduce` removes animation and smooth scrolling. Loading indicators run only while requests are pending.

Keep controls keyboard accessible, retain visible focus indicators, and let the mobile navigation close with Escape and restore focus. Horizontal scrolling belongs inside the hourly strip, never the whole page. Avoid autoplay decorative loops, fake performance percentages and ornamental controls without an action.

Mobile controls use at least 44px touch targets and editable selects keep a 16px font. Below 370px, the suburb refresh action keeps its accessible text while showing only the icon, leaving room for the full suburb name. Opaque mobile headers and bottom navigation avoid filtering the scrolling page behind them. Do not impose a body minimum width that exceeds the viewport after scrollbars are accounted for.

Load the shared font from each HTML entry so its discovery does not depend on downloading application CSS. Shared feed polling and clocks pause while the document is hidden; returning updates freshness immediately and resumes a single overdue poll. Existing timestamp validation, cancellation and expiry rules still apply. Reuse Melbourne date/time formatters during forecast interaction instead of constructing them for every rendered hour.

## Scope and verification

The redesign changes presentation, forecast interaction and EPA station browsing. EPA collection, backend secrets, PTV readiness, source timestamps, expiry rules and location-specific request cancellation remain in their existing modules. PTV live data stays unavailable until authorised credentials and production verification are complete.

`weather.html` is a separate Vite entry with weather and UV requests only. It shares the homepage's stored suburb choice. Weather refreshes every 15 minutes, becomes delayed after 30 minutes and expires after 90; station UV refreshes every minute, becomes delayed after 5 minutes and expires after 15. Expired weather also removes weather-derived UV forecasts and daylight values. A failure in either source must not suppress valid data from the other.

`air.html` is a separate Vite entry that requests EPA snapshots and the regional air model only, sharing the same stored suburb choice. Each EPA field becomes delayed after 90 minutes and expires after 180 minutes independently. The station list excludes sites with no recent field and preserves complete-snapshot withdrawals. The model also becomes delayed after 90 minutes and expires after 180 minutes. Neither source supplies a substitute for a missing value from the other.

`transport.html` is a separate Vite entry for the GTFS stop directory and, once enabled, the transport-only service. It shares saved stops and directions with the homepage through browser storage. PTV runtime credentials stay in the backend; the public page receives only validated transport data. When configured, the board polls every 30 seconds and hides departures and associated service updates after two minutes without a successful lookup. The displayed lookup time is not an upstream observation timestamp.

The EPA provider key remains a backend Secret. GitHub Actions uses its separate `EPA_BACKEND_TOKEN` Secret to collect and validate data from the owner-private backend, then publishes the snapshot consumed by the browser. The new page preserves that boundary and does not change backend access or expose either credential.

Run `npm run verify`, then inspect all page entries in the production build at desktop and narrow mobile sizes with actual data. Check hourly/daily switching, keyboard forecast selection, suburb switching, mobile navigation, source failures and expiry. For the weather page, also check valid observed UV zero, missing model UV, Melbourne-midnight rollover and the sunrise/sunset diagram. For the air-quality page, check station search, manual selection and nearest-station reset, selected-station fallback, partial missing fields, valid zero, per-field expiry and withdrawal by a newer snapshot. Confirm the public build contains no provider key or backend access credential. Production publication continues through the existing GitHub Pages workflow; do not move any provider secret into browser configuration for a visual change.

For navigation, verify every series link on all five pages, same-tab transitions, browser Back and current-page highlighting. Test 320 px mobile layouts, the open drawer's focus trap, Escape, background scroll lock and resize cleanup. Check that the bottom bar clears the last content and parking-map controls, and that it stays out of the open drawer's keyboard order.

For transport, verify the deployed pending state, real directory search, saved-stop restoration and official links. Confirm no live transit request is made before activation. Use local-only fixtures to check live/scheduled distinctions, cancellations, selected-stop changes, service-update details and shared expiry; never publish fixture departures. A successful visual release does not establish that the live PTV connection has been activated or verified.
